## 背景・目的

DA自治会の組織体制（学生支援班・アンケート班・広報班・プロジェクト・DA自治会推進委員会）ごとの出来事・予定を、班員それぞれが自分の端末から追加でき、全員がリアルタイムで同じ年表を見られるWebアプリを作る。年表は縦に伸びていく横書きレイアウトで、印刷にも対応する。

## アーキテクチャ

単一の `index.html`（HTML/CSS/JS、ビルド不要）+ Firebase Firestore（CDN経由のJS SDK, モジュール版 `firebase/app`, `firebase/firestore`）。既存プロジェクト（goshoin-map等）と同じ「単一ファイル・静的サイト」パターンを踏襲する。

- **データ保存**: Firebase Firestoreのコレクション `events`
- **ホスティング**: GitHub Pages（`main`ブランチ直下の`index.html`）
- **認証**: なし（Firebase Authは使わない）。追加・削除は合言葉（共通パスワード）による簡易ガードのみ

### Firebaseプロジェクト情報（設定済み）

- プロジェクトID: `dachronology`
- Firestore ロケーション: asia-northeast1 (東京)
- `firebaseConfig` はユーザーから提供済み（apiKey等はpublicなクライアント設定であり、セキュリティはFirestore側のルールで担保する）

## データモデル

Firestoreコレクション `events` の1ドキュメント:

| フィールド | 型 | 説明 |
|---|---|---|
| `date` | string (`YYYY-MM-DD`) | 出来事・予定の日付。`<input type="date">`（カレンダー）で選択 |
| `team` | string | 班・カテゴリ。下記6種のいずれか |
| `eventType` | string | 予定種別。下記6種のいずれか |
| `title` | string | 内容（必須、自由入力） |
| `memo` | string | 補足メモ（任意） |
| `createdAt` | timestamp | 作成日時（サーバー側`serverTimestamp()`） |
| `deleted` | boolean | 論理削除フラグ（既定 `false`） |
| `pass` | string | 書き込み時に送信する合言葉（Firestoreルール検証用。保存はされるが表示はしない） |

### team（班・カテゴリ）と色

| team値 | 表示名 | 色 |
|---|---|---|
| `support` | 学生支援班 | 赤 `#a31f1f` |
| `survey` | アンケート班 | 青 `#1e88e5` |
| `pr` | 広報班 | 黄 `#fdd835`（文字は濃色で視認性確保） |
| `project` | プロジェクト | 紫 `#8e24aa` |
| `promotion` | DA自治会推進委員会 | グレー `#757575` |
| `all` | 全体共通（全班の予定） | 黒 `#212121` |

### eventType（予定種別）

定例会 / 班長会議 / 全体集会 / プロジェクト会議 / 行事 / 意見交換会（6種、固定のプルダウン）

## UI・レイアウト

### サイト全体のテーマカラー

サイト全体（ヘッダー、タイトル、ボタンなどのアクセントカラー）はDAの赤 `#a31f1f`（学生支援班と同じ赤）を基調とする。年表本体の各カードは班カラーで色分けするが、ヘッダーやフォームのボタンなど「アプリ全体のクロム」部分は赤で統一する。

### 年表本体

- 縦方向に伸びるタイムライン。日付昇順（古い→新しい、下に行くほど新しい）でカードが並ぶ
- 各カードは横書き、左側に班カラーの縦バー＋ドットで色分け
- カード内: 日付 / 班名バッジ（色付き） / 予定種別バッジ / タイトル / メモ
- 新しいデータはFirestoreの `onSnapshot` でリアルタイム反映（他の人が追加したら自動的に表示に出る）

### フィルター

- 画面上部に6つの班カラーのチップ（トグルボタン）
- クリックで各班の表示/非表示を切り替え（複数選択可、初期状態は全部ON）
- 「全体共通」も1つのチップとして扱う

### 追加フォーム

- 日付（`<input type="date">`）、班（プルダウン、色見本付き）、予定種別（プルダウン）、内容（テキスト）、メモ（テキスト、任意）
- 送信時に合言葉の入力欄を表示（初回のみ。正しければ`localStorage`に保存し次回から省略）
- 送信 → Firestoreに `addDoc`（`pass`フィールドに入力された合言葉を含める）

### 削除

- 各カードにゴミ箱アイコン。押すと合言葉を確認（未保存なら入力を求める）→ 一致すれば論理削除（`deleted: true`に更新）
- 一覧のクエリは `deleted == false` のみ取得

## 印刷対応

`@media print` で以下を適用:

- 追加フォーム・フィルターチップ・削除ボタンなどの操作UIを非表示
- タイムラインを1カラムのシンプルな縦一覧に整形（A4縦想定、余白調整）
- 各カードに `break-inside: avoid` を指定しページ途中で分断されないようにする
- 背景色は控えめに（インクを節約しつつ班カラーは識別できるよう、左バーの色は残す）

## セキュリティについて（合言葉方式の限界）

Firestoreルールは概ね以下の方針:

```
allow read: if true;
allow create, update: if request.resource.data.pass == "DA";
allow delete: if resource.data.pass == "DA";
```

- 合言葉「DA」は平文でドキュメントに保存され、読み取りは誰でも可能なため、**厳密な認証ではなく「誤操作・軽い荒らし防止のための簡易ガード」**という位置づけ
- Firestoreルール自体はクライアントから読み取れないため、URLだけを知っている部外者がAPIを直接叩いて書き込む、という簡易的な妨害は防げる
- 本格的なアクセス制御が必要になった場合は将来的にFirebase Authenticationの導入を検討する（今回はスコープ外）

## テスト方針

自動テストは設けない（既存プロジェクトと同様、静的HTML+手動確認のシンプルな構成のため）。実装後、ブラウザで以下を手動確認する:

- 追加フォームから各班・各予定種別でイベントを追加できる
- 合言葉が誤っている場合は追加・削除が拒否される
- フィルターチップで班ごとの表示切り替えが機能する
- 別ブラウザ/シークレットウィンドウで開いても同じデータが見える（Firestore共有の確認）
- 印刷プレビューでフォーム類が消え、年表が見やすく整形される
